# Phase 1 screenshot checks

Taken on 28 September 2026 from Tjommie 0.1.0 (branch `p1e-t15-visual-pass`, run from source in production mode with the static UI export), with Claude Code 2.1.283 and Codex 0.157.1 signed in, on Windows 11 at 100% scale. The window is 1440 x 900, the frames' size.

`packages/desktop/scripts/screenshots.ts` took every picture from the running app with two real Claude bots on Haiku, CV Writer and Pnet apply. Nothing is faked or injected; every state is one the bots really reached:
- Each picture is the whole window as Windows draws it, caption buttons included. `page.screenshot` leaves those out, and WF1's checks name them.
- The exchange, CV Writer's shared file and the approval cards come from real tool calls.
- The routine really ran three times, two minutes apart: to the end (Done), stopped while it waited to write a file (Stopped by you), and while Pnet apply was paused (Skipped).
- From WF8 on, Pnet apply waits for you (a real Write approval), and from WF5 on CV Writer is paused, so the chips, the members, the popover and the Agents cards show those states.

Each pair was compared for layout, sizes, colors and copy rules, not content, by measuring both images: rows, columns and colors, on the 1x and @2x exports. The fixes are in 7a92018 ("Match the Phase 1 screens to their wireframes"). "Matches" means within 1 to 2 px, apart from the differences listed after the table.

## Differences left as they are

- **Type.** The app uses Segoe UI Variable (plan 1D), the frames Inter, so text widths and wrap points differ by a few px.
- **Line heights.** The app uses the spec's 14/21 and 12/18 (and 13/18), where the frames use OpenPencil's default leading. Cards with wrapped text are a little taller, as `docs/design/wireframe-spec.md` allows: the Browser card by 8 px, the Suggestion cards by 6, the Bots card by 5, two-line bubbles by about 8.
- **WF5 (from Task 11's report).** The room's header has no More button: nothing in Phase 1 would go in it. The room's composer has no Attach button: room posts carry no files (`room.post` takes text only). File cards in room posts have no size line: exchange posts store only the file's name and path.
- **The dialog scrim doesn't dim Windows' caption buttons** (WF7, WF11's dialogs). Windows draws them above the page, so the page's scrim can't cover them. Dimming them needs the desktop bridge to recolor the title bar overlay while a dialog is open; that's a change to `packages/desktop`, not to the UI, so it's left for a ruling.
- **Content and state.** The bots' words, names, times, the number of bots and routines, and which states the bots were in at each shot differ from the samples, as the task allows. Working lasts only while a bot runs, so no shot holds it; the frames' Working chips and loaders are the same components as the Waiting for you and Paused ones shown.
- **The app icon** (`packages/desktop/assets/icon.svg`) keeps the older Team room mark on its own dark tile; only the UI's mark changed.
