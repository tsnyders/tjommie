# Quiet pill and Usage verification captures

These images contain synthetic bots, conversations, usage and provider readings. They do not show owner account usage, a real inbox, an invoice or a paid provider turn.

- `phone-layout.real.test.ts` drives the production desktop app in an isolated data root and unsigned account folders, from source or the explicit `TJOMMIE_TEST_EXECUTABLE`. The final delivery pass uses the packaged executable. The `agents`, `chat`, `details`, `routine`, `exchange`, `team-mention`, `members`, bot-form, `accounts` and `usage` captures are refreshed by that test. `native-browser-360.png` uses an OS-composited capture of the same owned fixture window; its local page background is counted to ensure a native view is present.
- `packages/ui/visual/provider-usage.real.test.ts` renders the actual provider-card component and built CSS in Chrome at 360, 390 and 650 px, in both themes. The provider names, plan labels, percentages, credits and sample identity are deliberately supplied fixtures. It checks unknown percentages and stale readings without reading any credentials or contacting a provider.
- Each capture's suffix states its viewport and theme where applicable. Earlier captures may be overwritten during correction and final verification; the implementation plan records the final completed gates.
- `android-*` captures come from the owner's authorized S25 Ultra (Android 17), with Tjommie checked as foreground and the lock screen absent before capture. The disposable PC fixture has unsigned accounts and paused bots; approval and token-cost rows are synthetic. Keyboard/composer bounds are checked numerically; evidence captures hide the system keyboard. Pairing, real swipe scrolling in both directions, bot creation, a bounded Team room mention list, chat, approval, Android Back, Usage, reload/reconnect and revocation are exercised by `android-companion.real.test.ts`. The initial screen has an empty pairing-code field. No owner bots, credentials or live provider readings are captured.

Run the named real tests explicitly after `npm run build`. They do not belong to the default fast suite. Do not run the broad real-provider suites for this visual work.
